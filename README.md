# ModelMirage

Клиентский Fabric-мод **0.3.1** для Minecraft **26.2**, JDK **25**. Loadout changer для предметов, моделей игроков и анимированных персонажей из каталога. Подмена действует на все экземпляры выбранного типа предмета только в твоём клиенте; сервер получает обычные предметы.

## Использование

1. Установи ModelMirage и Fabric API для 26.2.
2. В мире нажми **Right Shift**.
3. В **Предметы** выбери предмет из сетки или найди его по названию/ID, например `diamond_sword` (печатать можно сразу, поиск откроется сам).
4. Выбери модель. Мод скачает JSON и зависимые PNG, проверит размеры и SHA-256 и подготовит отдельный texture atlas.
5. Посмотри preview справа: перетаскивание вращает модель. Нажми **Применить**. **Сброс** возвращает обычную модель предмета.

Загрузка проходит в фоне, без перезагрузки ресурспаков и её экрана. Выбор сохраняется в `config/modelmirage.json`. Проверенный каталог и файлы хранятся в `config/modelmirage/cache/`, поэтому ранее загруженные модели доступны без сети. Кнопка обновления в карточке игрока (или **Настройки → Каталог**) запрашивает каталог заново.

## Меню и HUD

Меню — окно из «жидкого стекла» с раскладкой в духе neverlose/Nixware.
Стекло рисуется собственным шейдером: перед отрисовкой GUI кадр мира
копируется в текстуру, под окном он размывается, у краёв преломляется,
сверху ложится тонировка и световой кант. Слева навигация:

- **Модели** — Предметы, Своя модель, Другие игроки, Персонажи. Слева сетка
  плиток с живыми preview, справа карточка предпросмотра с кнопками
  **Применить**/**Сброс**. Внутри предмета заголовок становится
  `Предметы / Предмет`; клик по «Предметы», Esc или кнопка «назад» мыши
  возвращают к сетке.
- **Визуалы** — HUD (общие настройки и карточка каждой панели) и Экран
  (прицел, скрытие scoreboard/boss bar).
- **Система** — Применённые (весь loadout со сбросом по пунктам) и Настройки
  (акцент, масштаб меню, размытие стекла, затемнение, анимации, каталог).

Настройки собраны в карточки: заголовок с переключателем модуля, строки
«подпись — контрол» (переключатель, слайдер с полем значения, выпадающий
список, цвет, клавиша, кнопка). Стрелки меняют значение выбранного слайдера
(Shift — шаг x10). В строке «Клавиша» клик и нажатие назначают клавишу,
Backspace/Delete удаляют, Esc отменяет. Ctrl+F или любой набранный символ
открывают поиск по текущей странице.

Каждая панель HUD — отдельный модуль: Watermark, Координаты, Цель, Эффекты,
Инвентарь, Броня, Активные модули, Клавиши. У каждой есть фон (стекло,
тёмный, нет), тень и свои элементы: например, у Watermark можно включить
логотип, FPS, пинг, ник, время и голову игрока. Общие параметры — масштаб
HUD, размытие и тонировка стекла, цветные иконки. Пустые инвентарь и броня
в игре не показываются.

**ПКМ по любой панели** в открытом чате или в редакторе HUD открывает
стеклянное окно её настроек рядом с панелью. Изменения видны сразу и
сохраняются. Esc закрывает это окно раньше чата или редактора.

**Редактор HUD** (кнопка на странице HUD) показывает все панели, включая
образцы для пустого инвентаря, брони и эффектов, а выключенные — полупрозрачными.
Перетаскивание привязывает панели к краям, центру и другим панелям; колесо
меняет масштаб панели; стрелки двигают её на 1 физический пиксель, Shift — на 10;
Backspace возвращает выбранную панель на место; двойной клик центрирует;
Ctrl+Z отменяет. В открытом чате также доступны перетаскивание, масштаб и
настройки видимых панелей.

Позиции и масштаб сохраняются в `config/modelmirage/hud.json`, настройки
модулей — в `visuals.json`, оформление — в `appearance.json`. Старые
`visuals.json` с переключателями панелей внутри «Интерфейса» переносятся
автоматически; устаревшее значение одной настройки пропускается, не сбрасывая
остальные. В моде нет боевых модулей, изменения мира и музыкальной интеграции.
Скелетные анимации и модели рук не входят в текущий статический загрузчик игроков.

## Каталог

Официальный источник: [ModelMirage-catolog](https://github.com/hhhhhffd/ModelMirage-catolog). Сейчас в нём **Blood Axe Mace**. Модель и её текстура загружаются из каталога и не входят в JAR мода.

Встроенный загрузчик `java-item` поддерживает Minecraft JSON: cuboid geometry, `minecraft:item/generated`, `minecraft:item/handheld`, display transforms, статические PNG и родительские модели. Собственные parents и текстуры перечисляются в записи каталога; vanilla parents доступны из ресурсов Minecraft. Блоки в мире, надетая броня, анимированные текстуры предметов и сложные item definition graphs пока не поддерживаются. Старый предметный формат и его валидатор описаны в репозитории каталога.

Каталоги `schema: 1` продолжают работать. Для новых записей используй
`schema: 2`; машинная схема — [docs/catalog.schema.json](docs/catalog.schema.json).
В записи модели задаются `kind` (`item`, `player`, `mascot`), `format`,
файл `model`, зависимости `textures`/`parents`; необязательные `group` и
`color` задают подпись категории и цвет полосы плитки, `items` ограничивает
применимые типы предметов. Без `kind` запись считается предметной.
У каждого файла остаются относительный `path`, SHA-256 и точный `bytes`.
Каталог ограничен 4096 записями / 2 MiB; пакет ассетов — 32 MiB.

Для персонажей встроен `sprite-animation`. Его файл `model` содержит:

```json
{
  "width": 64,
  "height": 64,
  "frame_time_ms": 100,
  "frames": ["modelmirage:my_character/frame_0", "modelmirage:my_character/frame_1"]
}
```

Все ID кадров перечисляются в `textures` записи каталога и указывают на PNG.
До 256 кадров, размер панели 8–512, интервал 16–2000 ms. PNG ограничены
2048×2048 и суммарно 16 Mi pixels. Загрузка, проверки, кеш и установка
текстур выполняются через общий каталог; resource reload не нужен.

### 3D-форматы (Blender, OBJ, FBX, glTF)

Для `kind: item` и `kind: player` встроен декодер на Assimp (LWJGL 3.4.1,
та же версия, что у Minecraft): `format` — `obj`, `fbx`, `gltf`, `glb`,
`dae`, `3ds`, `ply`, `stl`, `blend` (или `blender`). Для Blender надёжнее
всего экспорт в `.glb`: текстуры встраиваются в файл.

- Геометрия всех мешей запекается с трансформами узлов, вписывается в блок
  1×1×1 и получает позы `minecraft:item/handheld`; в GUI модель показана под
  углом, как блок. Модель игрока масштабируется по росту игрока.
- Текстура материала (base color/diffuse) берётся из встроенных в файл
  (`*0`, GLB/FBX) или из `textures` записи по имени файла без расширения
  (`map_Kd textures/Blade.png` → `modelmirage:sword/blade`). Если в файле
  нет ни одной текстуры, единственная текстура записи ложится на всё.
  Материал без текстуры рисуется своим цветом (`Kd`/base color, прозрачность
  `d`/opacity).
- Сопутствующие файлы (`.mtl`, `.bin` для `.gltf`, до 4 MiB каждый) перечисляются в `parents`,
  например `"modelmirage:sword/sword.mtl"`. Assimp видит только файлы записи
  (совпадение по имени без учёта регистра), но не диск.
- Ограничения: до 100 000 треугольников, текстуры до 2048×2048; скелетная
  анимация и морфы не воспроизводятся — используется статическая поза.

`format` не привязан к жёсткому списку. Записи с форматом без декодера видны
с пометкой «Нужен загрузчик» и не мешают остальному каталогу.

Новый декодер регистрируется кодом мода через
`CatalogService.registerLoader(format, kinds, loader)`. `ModelLoader.prepare`
получает уже проверенные байты файла и зависимостей в рабочем потоке;
`Prepared.install` вызывается в потоке Minecraft, `discard` освобождает
неустановленные ресурсы, если каталог изменился во время загрузки.
Загрузчик отвечает за cleanup при ошибке установки. Для 3D-геометрии можно
вернуть `RuntimeModels.Prepared` с собственным `ResolvedModel`: формат
входного файла остаётся обязанностью декодера. У каждого формата должен
быть свой декодер; файлы из каталога не исполняются как код.

Для своего источника передай JVM-параметр `-Dmodelmirage.catalogUrl=https://example.com/index.json`. HTTP разрешён только для localhost при разработке.

## Сборка

Нужен JDK 25:

```bash
JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew build
JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew runClient
```

Готовый JAR: `build/libs/ModelMirage-0.3.1.jar`.

## Проверка через Minecraft Mod MCP

Запусти `./scripts/setup-mcp.sh`: скрипт скачает проверенный JAR Minecraft Mod MCP 0.4.1 для Fabric 26.2 в `run/mods/`. Bridge для MCP-совместимых агентов (stdio, формат Claude Code) описан в `.mcp.json`; ему нужен Node.js 20+. MCP не входит в релиз ModelMirage.

В текущей среде скриншоты через MCP работают, а команды нажатий и кликов не управляют GUI (`hook: false`). Для интерактивной проверки использованы Xvfb и `xdotool`.

Сценарии, результаты и скриншоты: [docs/TESTING.md](docs/TESTING.md).
