# ModelMirage

Клиентский Fabric-мод **0.3.1** для Minecraft **26.2**, JDK **25**. Loadout changer для предметов, моделей игроков и анимированных персонажей из каталога. Подмена действует на все экземпляры выбранного типа предмета только в твоём клиенте; сервер получает обычные предметы.

## Использование

1. Установи ModelMirage и Fabric API для 26.2.
2. В мире нажми **Right Shift**.
3. В **Inventory → Предметы** выбери предмет из сетки или найди его по названию/ID, например `diamond_sword`.
4. Выбери модель. Мод скачает JSON и зависимые PNG, проверит размеры и SHA-256 и подготовит отдельный texture atlas.
5. Посмотри preview: перетаскивание вращает модель, колесо меняет масштаб. Нажми **Применить**. **Сброс** возвращает обычную модель предмета.

Загрузка проходит в фоне, без перезагрузки ресурспаков и её экрана. Выбор сохраняется в `config/modelmirage.json`. Проверенный каталог и файлы хранятся в `config/modelmirage/cache/`, поэтому ранее загруженные модели доступны без сети. Кнопка **Обновить каталог** запрашивает каталог заново.

## Меню и HUD

Changer оформлен по референсу NL Inventory: тёмная боковая панель, сетка
самостоятельных плиток предметов с цветными полосами, свой 3D preview слева
и preview других игроков справа. Категории: **Предметы**, **Своя модель**,
**Другие игроки**, **Персонажи**. Выборы независимы; **Применённые** фильтрует
сохранённый loadout. Поиск и прокрутка работают в текущей категории.
Preview видимых моделей загружаются в фоне; весь каталог заранее не скачивается.

Моделей игроков в официальном каталоге пока нет. Интерфейс показывает обычного
Minecraft-игрока и пустое состояние. Основа уже поддерживает произвольную
статическую геометрию Minecraft JSON для себя и остальных игроков в preview
и третьем лице. Сброс одного назначения не затрагивает другое.

BoyKisser перенесён в **Персонажи**. Здесь выбирается встроенная анимация
или загружаемый PNG-персонаж, включается показ, назначается клавиша через ПКМ
по кнопке показа и открывается редактор расположения. Выбор моделей игроков
и персонажа хранится в `config/modelmirage/changer.json`.

В **Visuals** остаются настройки HUD. Сам HUD использует оформление
[AstolfoVisuals](https://github.com/SRS-0/AstolfoVisuals): оригинальные
MSDF-шрифты, иконки, компактные чёрные панели и голубой акцент. Шестерёнка
открывает оформление: цвет HUD, масштаб GUI, затемнение и анимации.

Watermark показывает FPS, ping, имя и голову игрока. HUD включает координаты
и BPS, цель с головой и плавными полосками HP/урона/поглощения, отдельные
карточки эффектов с иконками и таймерами, прозрачные инвентарь и броню,
активные модули, Keybinds, прицел и анимированного BoyKisser. Появление
панелей, изменение размеров и чисел, переключатели и прокрутка анимированы.
Масштаб учитывает GUI scale Minecraft.

ЛКМ по заголовку модуля включает его; ПКМ или средняя кнопка назначают
клавишу. При назначении **Backspace** удаляет клавишу, **Esc** отменяет.
Пробел переключает выбранный модуль, Enter назначает клавишу;
стрелки меняют значение выбранного слайдера. Поиск находит модули и их настройки.

**Редактор HUD** показывает все панели, включая образцы для пустого
инвентаря, брони и эффектов. Перетаскивание привязывает панели к краям,
центру и другим панелям. Колесо меняет масштаб отдельной панели;
стрелки перемещают её на 1 физический пиксель, Shift — на 10.
ПКМ или Backspace возвращают выбранную панель на исходное место;
двойной клик центрирует её по горизонтали, Ctrl+Z отменяет изменение.
Esc возвращает в меню. В открытом чате также доступны перетаскивание,
масштаб и сброс видимых панелей.

Позиции и масштаб сохраняются сразу после изменения в `config/modelmirage/hud.json`;
старые записи без масштаба читаются с масштабом 1. Настройки модулей и оформления
хранятся в `visuals.json` и `appearance.json`. Уже сохранённые настройки
не заменяются новым расположением по умолчанию. В моде нет боевых модулей,
изменения мира, шейдеров рук и музыкальной интеграции. Скелетные анимации и
модели рук не входят в текущий статический загрузчик игроков.

## Каталог

Официальный источник: [ModelMirage-catolog](https://github.com/hhhhhffd/ModelMirage-catolog). Сейчас в нём **Blood Axe Mace**. Модель и её текстура загружаются из каталога и не входят в JAR мода.

Встроенный загрузчик `java-item` поддерживает Minecraft JSON: cuboid geometry, `minecraft:item/generated`, `minecraft:item/handheld`, display transforms, статические PNG и родительские модели. Собственные parents и текстуры перечисляются в записи каталога; vanilla parents доступны из ресурсов Minecraft. Блоки в мире, надетая броня, анимированные текстуры предметов и сложные item definition graphs пока не поддерживаются. Старый предметный формат и его валидатор описаны в репозитории каталога.

Каталоги `schema: 1` продолжают работать. Для новых записей используй
`schema: 2`; машинная схема — [docs/catalog.schema.json](docs/catalog.schema.json).
В записи модели задаются `kind` (`item`, `player`, `mascot`), `format`,
файл `model`, зависимости `textures`/`parents`; необязательные `group` и
`color` задают подпись категории и цвет полосы плитки, `items` ограничивает
применимые типы предметов. Без `kind` запись считается предметной.
У каждого файла остаются относительный `path`, SHA-256 и точный `bytes`.
Каталог ограничен 4096 записями / 2 MiB; пакет ассетов — 32 MiB.

Для персонажей встроен `sprite-animation`. Его файл `model` содержит:

```json
{
  "width": 64,
  "height": 64,
  "frame_time_ms": 100,
  "frames": ["modelmirage:my_character/frame_0", "modelmirage:my_character/frame_1"]
}
```

Все ID кадров перечисляются в `textures` записи каталога и указывают на PNG.
До 256 кадров, размер панели 8–512, интервал 16–2000 ms. PNG ограничены
2048×2048 и суммарно 16 Mi pixels. Загрузка, проверки, кеш и установка
текстур выполняются через общий каталог; resource reload не нужен.

`format` не привязан к жёсткому списку: `blender`, `gltf`, `obj`, `fbx` и
другие записи можно добавить уже сейчас. Пока соответствующий загрузчик
не установлен, они видны с пометкой «Нужен загрузчик» и не мешают остальному
каталогу. Сам импорт Blender/Blockbench/FBX в этом патче не реализован.

Новый декодер регистрируется кодом мода через
`CatalogService.registerLoader(format, kinds, loader)`. `ModelLoader.prepare`
получает уже проверенные байты файла и зависимостей в рабочем потоке;
`Prepared.install` вызывается в потоке Minecraft, `discard` освобождает
неустановленные ресурсы, если каталог изменился во время загрузки.
Загрузчик отвечает за cleanup при ошибке установки. Для 3D-геометрии можно
вернуть `RuntimeModels.Prepared` с собственным `ResolvedModel`: формат
входного файла остаётся обязанностью декодера. У каждого формата должен
быть свой декодер; файлы из каталога не исполняются как код.

Для своего источника передай JVM-параметр `-Dmodelmirage.catalogUrl=https://example.com/index.json`. HTTP разрешён только для localhost при разработке.

## Сборка

Нужен JDK 25:

```bash
JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew build
JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew runClient
```

Готовый JAR: `build/libs/ModelMirage-0.3.1.jar`.

## Проверка через Minecraft Mod MCP

Запусти `./scripts/setup-mcp.sh`: скрипт скачает проверенный JAR Minecraft Mod MCP 0.4.1 для Fabric 26.2 в `run/mods/`. Bridge для MCP-совместимых агентов описан в `.mcp.json`; ему нужен Node.js 20+. MCP не входит в релиз ModelMirage.

В текущей среде скриншоты через MCP работают, а команды нажатий и кликов не управляют GUI (`hook: false`). Для интерактивной проверки использованы Xvfb и `xdotool`.

Сценарии, результаты и скриншоты: [docs/TESTING.md](docs/TESTING.md).
